# Datapilot — RAG 问答与评测一体化平台

Datapilot 是一个面向企业与个人的 RAG（检索增强生成）开发与运行平台。它既能像知识库问答系统一样，把 PDF 等文档上传入库、自动解析整理并建立索引，再通过内置智能对话助手基于知识库内容回答问题；也内置完整的 RAG 评测体系——评估集管理、在线评测与评估看板，对问答效果逐题打分、回归对比并沉淀报告，辅助开发者持续调优 RAG 系统。

## ✨ 核心功能

- **文档入库**：上传 PDF 文档，自动完成解析、切分、摘要生成并建立索引
- **智能问答**：基于知识库的对话助手，回答有依据、可追溯
- **精准检索**：融合多种检索方式，从海量文档中快速定位相关内容
- **语义缓存**：相似问题直接命中缓存，响应更快、成本更低
- **评估集管理**：可视化维护评估集与用例（三态管理、批量导入、一键导出），替代手改评测脚本
- **在线评测**：一键运行评估集，逐题调用问答服务打分，结果入库、历史可追溯
- **评估看板**：历史趋势、通过率、失败用例等报告可视化，支撑回归对比与效果调优
- **用户与权限**：完整的注册登录与角色权限管理，安全可控
- **系统管理**：仪表盘数据概览、数据库查看、系统设置等一应俱全

## 🧩 系统组成

```
┌─────────────────────────────────────────────────────────┐
│                    浏览器（Web 管理端）                    │
│     仪表盘 · 智能对话 · 文档与评测 · 用户权限 · 系统设置   │
└─────────────────────────┬───────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
      核心服务          文档处理服务       检索问答服务
    用户 · 权限      解析 · 入库 · 建索引    检索 · 生成回答
    数据库管理
          │               │               │
          └───────────────┼───────────────┘
                          ▼
               数据库 · 向量库 · 缓存
```

- **Web 管理端**：浏览器访问的操作界面，涵盖数据概览、知识库问答、评估集管理与评估看板、用户与权限管理等
- **核心服务**：提供用户、权限、数据库管理、评估集管理等基础能力
- **文档处理服务**：负责 PDF 解析与知识库入库，让文档变成可检索的内容
- **检索问答服务**：负责知识检索与答案生成，是智能问答与在线评测的核心引擎

## 🚀 快速开始

### 开发环境

各服务分别启动：

| 服务 | 目录 | 启动方式 |
|------|------|----------|
| Web 管理端 | `client/` | `npm run dev` |
| 核心服务 | `services/core/` | `npm run dev` |
| 文档处理服务 | `services/doc-kit/` | 见 [doc-kit/README.md](services/doc-kit/README.md) |
| 检索问答服务 | `services/docs-seeker/` | 见 [docs-seeker/README.md](services/docs-seeker/README.md) |

详细步骤参见 [DEVELOPMENT.md](DEVELOPMENT.md)。

### 生产部署

进入 `deploy/` 目录，配置好环境变量后一条命令即可完成全部服务的部署，详见 [deploy/README.md](deploy/README.md)。

## 🗺️ 路线图

**✅ 已跑通**：文档入库 → 智能问答 → 评估集管理 → 在线评测 → 评估看板，评测与调优闭环已经成型。

**✅ 已完成 · chat 链路可观测**：`docs-seeker` 已接入 Langfuse 全链路追踪（`LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_BASE_URL` 或 `LANGFUSE_HOST` 环境变量；未配置时自动降级为 no-op）：

- 一个问答请求 = 一条 trace（`chat-response`），多轮会话用 `session_id` 分组（请求体可选字段），用户维度用 `user_id` 归因
- 语义缓存命中、查询分解、多路检索（dense/BM25/摘要）与 RRF 融合、向量化、LLM 生成等各环节的用时
- 大模型的输入与输出、模型名与 token 用量，方便回溯回答与成本核算
- 接入实现遵循 [Langfuse 官方 skill](https://github.com/langfuse/skills) 与[追踪最佳实践](https://langfuse.com/docs/observability/best-practices)：稳定命名、正确观测类型（retriever/generation/embedding）、输入输出只记录必要信息、测试环境自动禁用上报

**🎯 规划中**：

- 查询失败时，通过链路明细直接定位问题出在哪个环节（检索为空、缓存异常、模型超时……）
- 沉淀失败样本与耗时数据，为检索策略、文档切分与召回效果的持续优化提供线索
